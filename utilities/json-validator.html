Common JSON syntax errors explained

  • Trailing commas — the most common mistake. [1, 2, 3,] and {"a":1,"b":2,} are both invalid. Trailing commas after the last item are not allowed.
  • Single-quoted strings — JSON mandates double quotes. {'name':'Ali'} is not valid JSON, even though it works as a JavaScript object literal.
  • Unquoted keys — {name:"Ali"} is JavaScript object notation, not JSON. All keys must be quoted strings.
  • Comments — // this and /* this */ are not valid inside JSON. Use JSONC format if you need comments in config files.
  • undefined, NaN, Infinity — these JavaScript values have no JSON equivalent. They cannot appear in a JSON document.
  • Unescaped control characters — raw newlines, tabs, and other control characters inside strings must be escaped: \n, \t, etc.

JSON vs JavaScript object literals

JSON is stricter than JavaScript object syntax. You can write a JavaScript object with unquoted keys, trailing commas, and single quotes — but none of those are valid JSON. When in doubt, always validate through a strict JSON parser like this tool before using JSON in an API, config file, or data pipeline.
