What CSS minification removes

  • Comments — /* … */ blocks stripped entirely
  • Whitespace — spaces around selectors, properties, colons, semicolons, and braces collapsed
  • Trailing semicolons — the last ; before a closing } is optional and can be removed
  • Zero units — 0px, 0em, 0rem etc. simplified to 0 — the unit is meaningless for zero values

Minification vs compression

These work at different levels and are complementary. Minification reduces the raw character count by removing unnecessary tokens. Compression (gzip or Brotli) then encodes patterns in the remaining content. Most web servers apply Brotli or gzip to CSS automatically. Minifying first gives the compressor less redundancy to work with, but because minification itself removes repeated whitespace tokens that compress well, the net gain is typically 5–15% additional reduction on top of compression alone.

When not to minify

Never minify files you intend to debug directly in DevTools. Use source maps in your build process — they let browsers display the original formatted CSS while serving the minified version to users. Minifying without source maps makes debugging significantly harder.
