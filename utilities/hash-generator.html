Hash algorithm comparison

  • SHA-256 — 256-bit (64 hex character) output. Current standard for most security applications. Used in TLS certificates, code signing, Bitcoin, and most modern protocols. Use this by default.
  • SHA-512 — 512-bit (128 hex character) output. Larger output, stronger security margin. Marginally faster than SHA-256 on 64-bit processors. Use when the extra margin matters.
  • SHA-1 — 160-bit (40 hex character) output. Deprecated for security use since 2017 due to practical collision attacks. Still used in Git commit hashes and some legacy checksum scenarios — not for passwords, signatures, or certificates.

Hashing vs encryption

Hashing is one-way: you cannot reverse a hash to recover the original input. Encryption is two-way: data can be recovered with the correct key. Never use general-purpose hashes (SHA-256 etc.) for password storage — use purpose-built password hashing functions: bcrypt, Argon2, or PBKDF2. These include salting and intentional slowness to resist brute-force attacks.

Toolenix uses crypto.subtle.digest() from the Web Crypto API — a native browser implementation, no third-party library required.
