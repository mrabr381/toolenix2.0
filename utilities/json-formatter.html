JSON formatting conventions

  • 2-space indent — default in the JavaScript ecosystem. Used by ESLint, Prettier, npm's package.json, and most JS/TS projects.
  • 4-space indent — common in Python (PEP 8) and Java ecosystems. Also used in many REST API documentation examples.
  • Tab indent — configurable per-editor, preferred in some Go and PHP codebases. Tab width is a display setting, not a file property.

Common JSON syntax errors

  • Trailing commas — {"a":1,} is invalid. Remove the comma after the last item in any object or array.
  • Single quotes — JSON requires double quotes. {'key':'value'} is invalid.
  • Unquoted keys — {key:"value"} is JavaScript object syntax, not JSON.
  • Comments — standard JSON has no comment syntax. Use JSONC or JSON5 if you need comments.
  • Undefined/NaN/Infinity — these JavaScript values are not valid JSON literals.

Key sorting

Sorting keys alphabetically is useful when diffing two JSON blobs to see what changed, when ensuring deterministic serialisation order, or when working with version-controlled JSON config files where key order changes create noisy diffs.
